# Activity details (RUN-79)

`/app/training/[id]` authenticates the athlete and reads saved summary metrics and ordered, owner-scoped laps. Activity History links preserve the committed history query for the return link. Malformed, missing, and other-owner IDs never download FIT. ADMIN has no health-data bypass. Saved data remains available after Garmin disconnect.

The page follows the existing dark theme with one compact summary card containing all available metrics, a lap table/mobile cards, and Overview, Charts, Laps and Source tabs. FIT-only metrics join the summary after download. Loading uses skeletons without visible loading copy. The initial render, Laps and Source use Neon only. Unsupported summary fields are omitted; missing readings remain unavailable. No estimated effort classification, training advice, invented location, device, body battery or medical claims are displayed.

Opening Charts or explicitly loading/refreshing FIT sends an authenticated, same-origin POST to `/api/activities/[id]/charts`. The server validates the UUID, owner, provider, external numeric activity ID and verified Garmin account. It uses the existing provider lease, quota, credential snapshot and account verification before downloading through the existing bounded `requestFit` adapter. The same verified-owner, account, credential and request-limit checks apply in every deployment environment. The connection and saved activity snapshot are rechecked after download, so disconnects, replacements and deletions invalidate in-flight results.

The existing FIT decoder handles raw FIT and ZIP with integrity checks, archive path/CRC/size limits and bounded decoding. Only normalized record fields needed for charts and GPS are returned. FIT session start, distance, duration and recognized single-session sport must match the saved activity. UTC record timestamps become elapsed seconds from the verified session start; no browser timezone offset is applied to the stream. Enhanced FIT speed/altitude take precedence, SI units remain canonical, GPS semicircles become degrees, and running cadence becomes steps per minute while cycling cadence remains revolutions per minute.

Responses are private/no-store. Credentials, raw binaries, unknown fields and device identifiers are never returned. Errors use safe codes and preserve provider Retry-After/cooldown information. Operational quota/lease metadata is reused, but no activity/lap rewrites, FIT/ZIP files, GPS or per-second records are persisted. No schema changes or migrations are required.

The current mounted detail view caches decoded data and an in-flight promise, reusing both across tab switches and preventing overlapping fetches. It aborts an outstanding request on unmount and uses no browser storage or global health-data cache. Explicit Refresh replaces the transient data; a failed refresh retains the last successful charts. Errors require explicit retry; tab switching does not create retry loops, and cooldowns disable retry until expiry.

Charts support pointer/touch inspection, a shared cursor with visible elapsed-time/distance labels, keyboard navigation directly on each chart, time/distance axes and optional trailing 5/15-second smoothing. Left/Right inspect adjacent samples, Home/End jump to the boundaries, and Escape clears inspection. Missing measurements and recording gaps are not filled. Non-continuous distance disables distance mode. At most 4,000 representative samples are returned, retaining the first/last point, with source count and typical original sampling interval disclosed. Full-resolution statistics are not inferred from downsampled records. FIT session power, training effect, temperature and zone durations appear only when actually supplied and valid; multisport sessions do not borrow one segment's totals.

The route lazy-loads MapLibre GL JS with the MapTiler Streets v4 dark basemap, city/road labels, wheel/pinch zoom, drag/keyboard navigation, scale, attribution and fit-to-route controls. It mounts only after detailed FIT data is loaded and a valid route exists. GPS is supplied as an in-memory GeoJSON overlay, not uploaded to MapTiler. Missing fixes and recording gaps break the line; dateline crossings use nearby world copies. MapTiler receives browser requests for styles/fonts/sprites/tiles, exposing the viewed region and normal request metadata; no workout IDs or metrics are added to those requests. Missing configuration, WebGL/network errors and retry have explicit states without hiding charts. Map instances, resize observers and workers are released on unmount.

Set `NEXT_PUBLIC_MAPTILER_API_KEY` before building Next.js. This is intentionally a public browser map key; restrict its allowed origins in MapTiler Cloud. Keep Garmin credentials server-only. Storybook maps are optional: export this public key when building/running stories to enable live basemaps with synthetic routes. Without it, stories show the configuration state and make no MapTiler requests.

Both Overview and Charts show the route beside an interactive heart-rate zone doughnut with recorded duration and percentage per zone. The center shows total recorded zone time or the inspected zone. Zone durations come from the single FIT session or one explicitly matching session-level `time_in_zone` message. Lap references, mismatched/ambiguous references and impossible totals are rejected. FIT index 0 remains below-zone-1 time; thresholds and durations are never inferred from the athlete profile or downsampled stream. Absent durations show an explicit empty state.

Zone labels retain their recorded numbers and add the standard Garmin five-zone names: Warm-up, Easy, Aerobic, Threshold and Maximum. Index 0 is labeled Below range; additional custom zones retain their recorded numbers. The full-width legend sits below the doughnut so zone names have room alongside aligned durations and percentages. The information tooltip explains perceived effort, the anaerobic contribution at maximum intensity, custom boundaries and the percentage denominator. It supports hover, keyboard focus and tap, with Escape, blur and outside-click dismissal. These are general descriptions, not inferred physiological thresholds or a workout training-effect classification. Names and descriptions follow [Garmin's zone guide](https://www.garmin.com/en-ZA/blog/fitness/how-you-can-train-by-heart-rate-zones-using-garmin/) and [heart-rate zone table](https://www8.garmin.com/manuals/webhelp/GUID-85E8D94D-E009-4EDD-A980-C9EE59C1F323/EN-US/GUID-A8716C0B-B267-4C42-B45F-B9C7928BCA19.html).

Metric charts with no recorded values on the selected axis are omitted, including their labels and empty placeholders. If no metric is available, the entire charts card is omitted while route, zones and saved workout details remain independently available.

Zone sectors use filled annular SVG paths, including a dedicated full-ring case when only one zone has recorded time. This avoids dashed-stroke artifacts at very small zone durations while preserving hover, touch and keyboard inspection. The route map fills its available card height beside the stacked diagram/legend. Redundant Private badges and the Visibility row are omitted.

Tests use synthetic FIT/ZIP binaries and display fixtures. They cover isolation, disconnected saved reads, unsafe IDs, credential changes, deleted activities, rate limiting, safe error responses, record identity/units, malformed/oversized files, deduplication, tab behavior, missing metrics, responsive component stories and interactive controls. Live Garmin calls and physical-device verification are not part of automated validation.

Records at the same timestamp are coalesced before display sampling: later non-null metrics fill missing fields, while the first valid measurement wins conflicts, including recorded zero values. GPS fixes remain complete pairs. In distance mode, pointer and keyboard inspection use only points with known distances; changing axes or refreshing data resolves the selection to the nearest valid timestamp. Time mode keeps all timepoints, and a live region exposes the inspected time/distance to assistive technology.

Trace spacing uses the retained display points rather than the original sampling interval. During reduction, per-series `breakBefore` markers preserve recording gaps and missing sensor/GPS fixes that would otherwise be skipped. Charts, smoothing and route lines honor those markers without disconnecting a continuous long recording merely because its displayed points are further apart.

Metric gaps are counted across all samples before filtering for the horizontal axis. Distance mode therefore preserves missing sensor readings even when those same points have no recorded distance, including recordings that do not require reduction. Valid zero readings remain continuous; zero running speed leaves pace unavailable.
