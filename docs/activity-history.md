# Training activity history (RUN-44)

`/app/training` lists saved activities of every sport. Apply filters commits title search, sport, date range, source (when multiple providers exist), minimum-distance presets to URL query parameters. Reset clears both the draft and URL. Sort and page-size changes reset pagination; Back/Forward restores committed filters. Page sizes are 10, 25 and 50. Invalid queries show a recoverable error.

`getActivityHistory(owner, query)` in `src/server/activity/history.ts` returns a bounded page and owner-scoped counts/filter options. It shares verified-account visibility with the existing activity list/detail services. Saved records remain readable after disconnect. Unverified legacy Garmin rows and records associated with a different Garmin account stay hidden. No provider requests or FIT decoding occur on page load, filtering, sorting or pagination. The existing activity API cursor contract is unchanged.

Count and page reads share a repeatable-read transaction. All ordering ends with the activity UUID to make equal timestamps deterministic. Distance sorting places nulls last. Out-of-range page numbers are clamped; only one page is fetched. Concurrent imports can change page contents between separate requests: history is a live view, not an immutable snapshot.

Dates and date filters use the browser's local IANA timezone. The browser saves a non-sensitive timezone cookie; if the server used another zone on the initial request, the list shows a skeleton until a saved-data refresh applies the correct timezone. Before the browser timezone is available, the server falls back to the profile timezone and then UTC. Calendar-day boundaries handle DST and skipped local midnights. Custom end dates are inclusive, using the next local day as an exclusive SQL upper bound. The minimum-distance selector uses sport-specific presets: running offers 1/3/5/10 km, half marathon (21.0975 km), marathon (42.195 km), and Ultra; cycling uses kilometer thresholds from 5 to 200 km, walking uses 1 to 30 km, and swimming uses 100/250/500 m plus kilometer distances. All sports and unknown future types use generic kilometer thresholds. Changing sport preserves compatible thresholds and clears an incompatible one. The server validates each sport/distance combination. Numeric presets are inclusive minimum thresholds; Ultra requires more than 42.195 km. The HR-presence filter has been removed. Displayed distance, running pace and other-sport speed follow the saved measurement system.

The reusable `ActivityHistoryRow` includes title, sport, source, date and available summary metrics without raw records, GPS or laps. Duration prefers timer, then moving, then elapsed time and labels its meaning. Pace/speed uses supplied average speed, or distance and timer duration; missing metrics stay unavailable. Rows have no dead detail links while RUN-79 is pending.

The existing manual Garmin sync controller stays in the header as Sync now, using the established endpoint, authorization, rate limits, checkpointing and toast feedback. Historical import remains in Settings. Old saved/synced timestamps show a stale-history message. Disconnected or unavailable Garmin never suppresses saved history.

The layout follows Health: a desktop table and compact mobile rows using dark semantic tokens. Settings and history share `src/components/ui/Select/`, extracted from the existing custom dropdown pattern; custom ranges reuse DateField. Storybook covers populated, mobile, long-title, not-imported, empty, no-match and custom-date states.

No schema changes, migrations, charts, trends, plan edits or detail implementation are included. Tests cover another user's records (including an admin), disconnected history, equal-time pagination, composed filters, literal search characters, timezone boundaries, null/all-sport metrics, URL navigation and dropdown keyboard behavior.

During filter, sort, page-size and pagination requests, skeleton rows replace the table body rather than adding a spinner above it. Filter requests use the requested page size; navigation to a known last page uses its remaining row count. The current table height is reserved while loading. Controls share the global 40px default minimum (44px for coarse pointers), and compact actions use the shared compact size. Both pagination arrows remain matching squares sized from the control token. A no-match result is plain copy within the list, without a nested border or extra clear action.

All applicable filters are visible without a More filters disclosure; custom date inputs appear when Custom dates is selected. The result count uses compact label typography. Select menus match the trigger width, size to their content, and use consistent option padding. Hover/focus and the selected value have distinct treatments.

Filter layout keeps the status alongside Apply/Reset, and custom dates in the same form grid. Compact card padding and inline Sort by/Per page labels remove separate whitespace bands before and after the table.

Custom From/To controls share an equal-column date-range grid (stacked on narrow screens). Dropdowns hide native scrollbar chrome while retaining wheel, touch and keyboard scrolling, keeping rounded borders clear.

Custom calendars start at the first visible saved activity's local date, independent of the active filters, and end today in the same timezone. Empty history falls back to January 1, 2020. Another athlete's records and hidden Garmin accounts never affect these bounds. Older saved activities remain selectable even when they predate 2020. Sync status polling refreshes the saved history when the status changes, including when an active batch finishes or pauses after saving partial progress; unchanged polling statuses do not repeatedly reload the table.
