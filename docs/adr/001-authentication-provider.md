# ADR-001: Better Auth for private registration

**Status:** Accepted, revised 2026-10-31 for RUN-17.

## Decision

Use self-hosted Better Auth in the existing Next.js Node runtime with its
official Prisma adapter, the pinned Prisma 6.19 client and Neon PostgreSQL.
Email/password is the only enabled login method. Keep application roles in
`users.role` (`USER` or `ADMIN`); Better Auth stores credentials and sessions in
separate `auth_*` tables. Its user ID is stored in `users.auth_subject`. The
existing `users` table and dependent athlete records are retained.

Registration requires a high-entropy, one-time invitation URL generated by a
trusted operator CLI. The operator manually sends the URL through a private
channel. The URL token is hashed in Neon, expires after seven days, and an
atomic conditional update claims it before the Better Auth signup endpoint is
called. Invalid input is rejected before the claim, and a 4xx response from
Better Auth releases that exact claim for retry. Unknown server failures remain
fail-closed; the operator can issue another link.
Better Auth's password flow and session writes run in a Prisma transaction.
Rate-limit counters use the same PostgreSQL database so Vercel instances share
the limits.
The signup route rejects requests without a valid token, including direct API
calls. No provider dashboard, outbound email system, custom domain, or public
promotion endpoint is needed.

The invitation proves possession of the link. It does **not** verify ownership
of the email address entered at signup. Better Auth leaves `emailVerified=false`.
A future email verification feature must use a separate verified delivery flow.

## Consequences

- Preview and Production use independent Neon projects, auth secrets and stable
  `*.vercel.app` origins. Better Auth runs only in the server runtime.
- RUN-16 applies the checked-in additive migration before deployment and grants
  the runtime role access to the new auth tables.
- Existing Clerk users cannot sign in with their Clerk password or session.
  If real athlete rows exist, an operator must verify each identity and remap
  `users.auth_subject` explicitly before that user resumes access. Email alone
  is never used to attach an old athlete row.
- RUN-18 will add ADMIN-only invitation generation/list/revocation UI; RUN-20
  retains responsibility for broader tenant authorization.

See [Better Auth installation](https://www.better-auth.com/docs/installation),
[Prisma adapter](https://www.better-auth.com/docs/adapters/prisma), and
[database schema](https://www.better-auth.com/docs/concepts/database).
